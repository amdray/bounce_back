## Анализ: почему всё по-разному?

### Гипотеза 1: Оптимизация памяти J2ME

Оригинальный код писался для телефонов с 128-256KB RAM. Разные подходы могли быть продиктованы:

1. **Рампы** — часто используются, проще хранить 4 готовых PNG чем применять повороты на лету (быстрее рендер)
2. **Кольца** — редкие объекты, можно сэкономить на текстурах и крутить на лету

### Гипотеза 2: Разные художники/этапы разработки

Разные части игры могли делаться в разное время с разными подходами.

### Гипотеза 3: DirectGraphics vs обычный Graphics

В J2ME:
- `Graphics.drawImage()` — не поддерживает повороты
- `DirectGraphics.drawImage(..., manipulation)` — поддерживает, но медленнее

Для часто рисуемых объектов (рампы) могли создать все повороты заранее, чтобы использовать быстрый `Graphics.drawImage()`.

## ГЛАВНЫЙ ВЫВОД

**Поле `transform` имеет разные назначения:**

1. **Для коллизий** — transform ВСЕГДА применяется к маске (alias берёт маску base и поворачивает)

2. **Для рендера** — зависит от типа тайла:
   - **Тайлы с отдельными текстурами** (рампы): transform НЕ применяется к рендеру, текстура уже повёрнута
   - **Тайлы с одной базовой текстурой** (кольца): transform ПРИМЕНЯЕТСЯ к рендеру

### Как определить?

| Признак | Transform для рендера |
|---------|----------------------|
| `coll=1` (inline mask) | НЕТ, это базовый тайл с уникальной текстурой |
| `coll=3` (alias) + image отличается от base | НЕТ, текстура уже повёрнута |
| `coll=3` (alias) + image == base.image | ДА, нужно повернуть |

### Проблема текущего кода

Сейчас в `level_renderer.c` и `foreground_pass.c` transform применяется КО ВСЕМ тайлам:
```c
SDL_Texture* tex = tileset_get_ex(meta.image_index, meta.transform);
```

Это вызывает **двойной поворот** для рамп:
- Текстура 053 уже ◣ (90° CW от ◢)
- Применяем transform 0x01 (ещё 90° CW)
- Получаем ◤ вместо ◣!

### Правильная логика

```c
// Для коллизий: всегда использовать meta.transform
// Для рендера: использовать transform только если это "настоящий" поворот
int render_transform = should_apply_render_transform(tile_id) ? meta.transform : 0;
SDL_Texture* tex = tileset_get_ex(meta.image_index, render_transform);
```

Или проще: **if tile has inline mask (coll=1) OR different image from alias base → render_transform = 0**

## ИСПРАВЛЕНИЕ (2026-02-06)

**Первоначальная проблема:** В `level_renderer.c` применялся transform ко ВСЕМ тайлам:
```c
// БЫЛО:
SDL_Texture* tex = tileset_get_ex(lr->tileset, meta.image_index, meta.transform);
```

**Первый фикс (неполный):** Убрать transform для всех → сломались кольца.

**Финальный фикс:** Transform применять ТОЛЬКО для колец (tileId 93-104):
```c
// СТАЛО:
if (display_tile >= 93 && display_tile <= 104) {
    tex = tileset_get_ex(lr->tileset, meta.image_index, meta.transform);
} else {
    tex = tileset_get(lr->tileset, meta.image_index);
}
```

**Логика:**
- **Рампы (tileId 3-6, 113-116):** Все 4 ориентации — отдельные PNG, transform НЕ нужен
- **Кольца (tileId 93-104):** Один image переиспользуется с transforms, transform НУЖЕН
- `foreground_pass.c` (overlay для hoops) → transform применяется всегда
