# Замена god mode на native stone mode

## Цель

Убрать из порта читовый `god_mode`, который просто блокирует `player_kill()`, и заменить его на debug/dev-переключатель нативного игрового состояния `stone` (`tile 22`), чтобы поведение оставалось в рамках оригинальной механики игры.

Это должно дать:

- не "полную неуязвимость", а ровно те свойства, которые у камня есть в оригинале;
- единое поведение для коллизий, таймеров, анимаций и рендера;
- отсутствие отдельной читовой ветки внутри `player_kill()`.

## Почему текущий god mode плох

Сейчас `god_mode`:

- хранится отдельным флагом в [`src/player.h`](/mnt/d/OneDrive/VSCodeProject/psp/bounce_back/src/player.h);
- переключается по `L+R` в [`src/player.c`](/mnt/d/OneDrive/VSCodeProject/psp/bounce_back/src/player.c);
- просто делает ранний `return` в `player_kill()`.

Проблемы этого подхода:

- он не соответствует ни одному состоянию из оригинальной игры;
- он обходит реальную физику и collision-контракты;
- его поведение шире, чем stone mode: он спасает вообще от всего, а stone в оригинале спасает не от всего;
- он усложняет аудит соответствия Java, потому что в коде появляется отдельная "магическая" защита от смерти.

## Что должно быть вместо этого

Нужен не "god mode", а "debug stone toggle".

То есть кнопка `L+R` должна:

- включать игроку штатное состояние камня;
- выключать его, возвращая игрока в базовую форму через штатный state transition;
- не менять правила смертности за пределами того, что и так делает `is_stone`.

По смыслу это не чит "ignore death", а способ вручную активировать существующую игровую механику.

## Правильный архитектурный подход

### 1. Удалить семантику invincibility

Нельзя оставлять `god_mode` как "флаг, запрещающий death".

Нужно убрать из `player_kill()` проверку вида:

```c
if (p->god_mode) return;
```

После этого вся выживаемость игрока должна определяться только штатными состояниями:

- `is_stone`
- `is_inverted`
- `state_a`
- `state_r`
- `stunned`
- таймерами

### 2. Вынести debug-toggle в отдельную доменную операцию

Нужен helper уровня игрока, например:

```c
static void player_toggle_debug_stone(Player* p, Level* level);
```

или пара функций:

```c
static void player_enable_debug_stone(Player* p, Level* level);
static void player_disable_debug_stone(Player* p, Level* level);
```

Этот helper должен работать через существующие state machine, а не напрямую ломать поля без контракта.

### 3. Включение должно использовать нативную механику stone

При включении debug stone mode нужно использовать тот же контракт, что у `tile 22`.

Желательно переиспользовать уже существующую логику:

- `player_activate_stone_powerup(p);`

Но есть важный нюанс:

- `player_activate_stone_powerup()` сейчас не принимает `Level*`;
- она запускает state transition, но сама не делает collision-aware conversion;
- анимационные и размерные переходы выполняются позднее через `player_apply_r_state()` и `player_change_sprite()`.

Поэтому для debug-toggle нужно решить, что именно хотим:

- вариант A: запускать ту же анимацию и таймер, что у tile `22`;
- вариант B: мгновенно переводить в stone state, если это удобнее для dev usage.

Для parity-близкого поведения лучше вариант A.

### 4. Выключение должно быть штатным

При выключении нельзя просто писать:

```c
p->is_stone = false;
p->sprite_index = 0;
```

Это небезопасно, потому что:

- размер спрайта и маски меняется;
- нужен корректный `player_change_sprite()`;
- может понадобиться восстановление `stunned`, `state_r`, `timer_a`, `stone_timer`.

Правильнее:

- если игрок уже в stone form, запускать штатный выход через `state_r = 2` с `timer_a = 3`;
- либо сделать отдельный helper "force return to small form", но тоже через существующую sprite/collision pipeline.

### 5. Отдельно определить поведение таймера

Нужно заранее решить, что означает debug stone mode:

- "одноразово включить обычный stone с таймером 550"
- или "держать stone активным, пока debug toggle включён"

Рекомендация:

- для нативности лучше использовать обычный `stone_timer = 550`;
- повторное нажатие `L+R` может просто переактивировать/обновить камень;
- если нужен именно постоянный debug state, это надо делать отдельно и явно, не маскируя под обычный stone.

Иначе это снова будет чит, только под другим именем.

## Рекомендуемая реализация

### Вариант, который лучше всего сохраняет оригинальную механику

1. Удалить поля:

- `god_mode`

2. Переименовать:

- `prev_cheat_pressed` → `prev_debug_stone_pressed`

3. В `player_update()` оставить `L+R` как debug-input, но вместо `god_mode = !god_mode` делать:

- если игрок не stone: вызвать активацию stone через нативный helper;
- если игрок уже stone: обновить `stone_timer` или запустить штатный выход, в зависимости от выбранного UX.

4. Убрать `god_mode` из:

- `player_kill()`
- save/import/export state
- [`src/save.c`](/mnt/d/OneDrive/VSCodeProject/psp/bounce_back/src/save.c)
- [`src/player.h`](/mnt/d/OneDrive/VSCodeProject/psp/bounce_back/src/player.h)

5. Оставить весь collision behavior без special-case читов.

### Практически лучший UX для разработки

Для отладки я бы сделал такое поведение `L+R`:

- если `!is_stone`: активировать stone штатно;
- если `is_stone`: продлить `stone_timer = 550`.

Почему это лучший компромисс:

- нет отдельной "бессмертной" физики;
- поведение полностью нативное;
- не нужно проектировать сложный обратный toggle;
- кнопка остаётся полезной для тестирования.

То есть `L+R` становится "дать себе tile 22", а не "включить god mode".

## Чего делать не надо

### Не надо подменять один флаг другим

Плохо:

```c
p->god_mode = p->is_stone;
```

или:

```c
if (debug_mode) p->is_stone = true;
```

Это ломает state machine и создаёт скрытые контракты.

### Не надо вручную выставлять спрайт без collision-aware перехода

Плохо:

```c
p->sprite_index = 22;
p->is_stone = true;
```

Без `player_change_sprite()` и связанного обновления mask/dims это риск регрессий.

### Не надо оставлять fallback в player_kill

Если после замены в `player_kill()` останется special-case вида:

```c
if (debug_stone_mode) return;
```

то это уже не замена god mode, а просто его переименование.

## Минимальный безопасный план изменений

1. Удалить early-return по `god_mode` из `player_kill()`.
2. Переименовать `prev_cheat_pressed` в `prev_debug_stone_pressed`.
3. Убрать поле `god_mode` из `Player` и `PlayerSaveState`.
4. Сделать helper уровня игрока для активации stone через существующий контракт.
5. Привязать `L+R` к helper'у активации stone.
6. Решить одно из двух:
   - либо `L+R` всегда только переактивирует stone;
   - либо `L+R` работает как toggle с корректным штатным выходом из stone.
7. Проверить:
   - камень не умирает от статичных шипов;
   - камень ломает только `7/8`;
   - без stone игрок снова умирает штатно;
   - сохранение/загрузка не содержит старый `god_mode`.

## Рекомендация

Лучший вариант для проекта:

- полностью удалить `god_mode`;
- оставить `L+R` как debug action "дать игроку обычный stone power-up";
- не делать постоянную неуязвимость;
- не делать отдельный читовый bypass смерти.

Это даёт максимально чистую архитектуру и лучше соответствует задаче "переключение нативного режима игры".
